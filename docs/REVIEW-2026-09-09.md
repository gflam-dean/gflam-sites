# VenuePlay Trivia review (read-only, 7 Sep 2026)

Four people in the room: the player on a phone in a noisy pub, the host on a tablet, the manager, and the owner. Ranked best value first. Effort: S = under an hour, M = an afternoon, L = a day.

## Ranked list

### 1. Phone answers are always grey. The four colours never turn on
- Helps: player, host
- Today: the design calls for four different coloured answer buttons on the phone (Kahoot style), with a host toggle to switch between full text and A/B/C/D letters. The host console defaults `colour:false` (host.html line 349) and the code that would flip it listens for clicks on `#cfgColour button` (lines 902 to 905), but there is no `#cfgColour` element anywhere in the markup (only `#cfgSpeed` at line 207). So `colour` is broadcast as false on every message (lines 434, 440, 672, 679, 698, 790) and play.html adds the `neutral` class to every button (lines 318 to 320). Every phone in the pub shows four grey buttons. Nothing the host can do changes it.
- Should: add the missing toggle to the host settings panel (default on) so the phone shows four colours and the TV can match them. A player who has sunk a few beers picks "the blue one" far faster than reading four lines of 14px text.
- Where: venueplay/app/trivia/host.html lines 207, 349, 902 to 905; play.html lines 318 to 320
- Effort: S

### 2. The once-a-week limit only speaks up after the lobby is already on the TV

Your next trivia night is available from 2026-09-14." (venueplay-game.js lines 5577 to 5579). The room has already joined. The date is an ISO string, not "Monday 14 September".

- Where: venueplay-backend/worker/venueplay-game.js lines 5545 to 5580; venueplay/app/trivia/host.html lines 644 to 685

### 3. "End round" sits under "Reveal answer" with no confirm

### 4. A phone that sleeps or switches apps forgets the team name and misses the live question

Worse, when the token does survive, `ensureJoined()` (line 539) returns early without rebuilding from the snapshot, so the player sees the waiting screen, not the current question.
- Should: save the name to localStorage (one word change) and, on a token-only re-join, pull the snapshot and jump straight into whatever state the game is in.
- Where: venueplay/app/trivia/play.html lines 272 to 273, 539, 620
- Effort: S

The player is told they are in, then sees "No answer" on the result screen and thinks the game is rigged.

## Already good

The bones are solid. Scoring is done on the server and the correct answer is never sent to a phone before the reveal, so nobody can cheat by reading the network. Answers are stamped against a server deadline, and the speed bonus (up to half the base points, scaled by time left) is simple enough to explain in one sentence. The no-repeat rule works at two levels, within the night and across 12 months for the venue, so regulars do not hear the same question twice. The host console pre-fills the venue's last settings, the "Pick a question set first" guard stops an empty start, and the reveal-state End round does confirm. The TV flow reads well: question, timer, split bars, top five, roll to the leaderboard, then a podium with a proper celebrate beat, and it falls back to ads 18 seconds after the game goes idle so a screen never sits dead. The phone follows the host across trivia, musical and bingo pages (vp-follow.js) so a punter never needs a second QR code. The builder's topic search, themed packs and typed-name delete confirm are the right shape. The signing of host broadcasts and the venue-scoped set lookups mean a second venue cannot see or run another venue's set.

## Already good

The money side is careful in the places that matter most. Cancelling a venue rolls back if Stripe refuses the change rather than promising an end date it cannot keep; player increases and decreases use idempotency keys that describe the move so a quick up-down-up cannot double charge or mint credit; annual reductions bank a credit that is shown on the page; and busy-night overage can never block a host closing the night. The failed-payment path is complete: an email with a pay-now link, suspension only after repeat failures (more patience on annual), and automatic reactivation when the invoice pays. The welcome, group welcome, HQ welcome, upcoming payment and forwardable venue onboarding emails are plain, warm, carry the ABN and unsubscribe link, and explain overage in one paragraph a publican can follow. Opt-in exports are scoped to the owner's own venues, de-duplicated, audited, and held for review when the account does not look like a real venue. The group model works: one login switches venues, a group owner sees per-venue rows with pending changes and cancellations marked, managers can be scoped to a subset of venues, and the manager gates on the Your account page were fixed on 2 September so they actually hide what the owner switched off. Settings reads back after saving and tells the owner when the database refused a marketing toggle rather than pretending it saved.
