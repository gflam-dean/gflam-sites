# What to run when you are back, 9 Sep 2026

Everything below is built, tested and committed. Nothing has been pushed to main
and nothing live has changed. The order matters: the database first, then the
site, then the two Workers.

The work is already safe on GitHub on a branch called `build/review-2026-09-09`,
so nothing can be lost if any of this waits until tomorrow.

## Step 1. The migration (about 30 seconds)

Supabase SQL editor, paste and run:

    venueplay-backend/supabase/venueplay-74-members-draw-pending.sql

It lets the members draw write its record the moment a winner is picked instead
of only when the host resolves it. Until now, a draw whose reply was lost on bad
wifi left nothing behind at all: the date said "drawn tonight" and no row said
who. Safe to run twice. The Worker forgives its absence, so nothing breaks if
this waits, you just do not get the fix.

## Step 2. Push the site

    cd ~/gflam-ai-team/sites
    git push origin build/review-2026-09-09:main

The site deploys itself from main. This is the one that changes what a venue
sees, so do the live checklist afterwards (section at the end).

## Step 3. The game Worker

    cd ~/gflam-ai-team/sites
    python3 tools/deploy-worker.py --live venueplay-game venueplay-backend/worker/venueplay-game.js

Expect it to finish with `/health` reporting build `9d7b4457`.
This turns on: the trivia picture upload, editing a question, "+10 seconds" for
a question, the raffle console remembering unsold tickets after a reload, the
members draw pending record, and the phone agreeing with the wall on a tie.

## Step 4. The billing Worker

    python3 tools/deploy-worker.py --live venueplay-api venueplay-backend/worker/venueplay-api-FULL.js

Expect `/health` to report build `ab821ee7`.
Without this, seven account fixes do nothing, including the one that stops a
manager opening the owner's Stripe portal (every invoice, and the card).
Note this Worker was already behind before today: live is on a 5 Sep build.

## Step 5. Prove it

    python3 tools/release-check.py

It asks each Worker its own name and build. "I deployed it" is not evidence.

## Step 6. The live checklist

Only on The Mini Bar (slug `the-mini-bar`, join code `UZRHJU`). Never on
The Average Joe. The per-format lists are in the build reports; the short version:

1. Bingo: win a line and confirm the green banner stays up through the next ball.
2. Musical: two phones call bingo on the same song, both cards reach the host.
3. Trivia: build a night in the builder, add a picture question, run it, and
   check the picture fills the TV and sits above the options on the phone.
4. Members draw: draw, close the tab mid-draw, reopen, and confirm the same
   winner comes back rather than a second one.
5. Raffle: a win celebrates for the full 30 seconds and the TV never goes dark.
6. Every screen: no player count anywhere on the TV.
